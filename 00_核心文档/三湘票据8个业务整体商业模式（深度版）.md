## 一、核心商业模式：常松阳部 + 冷部 + 合作伙伴

### 1.1 原始理解（简化版）

过去我们的简单理解是：

```text
常松阳部（获客） → 冷部（操作 A/B 业务）
```

* 常松阳部 = 招兼职、拉客户
* 冷部 = 做 A 贴现 / B 承兑销售
* 其他业务（C–H）零散存在，没有系统纳入一套「前后端分离」结构。

### 1.2 升级后的完整理解

现在更准确的结构应该是：

```text
常松阳部（获客 + 接单 + 分发） → 多个后端处理节点
  ├→ 冷部（A/B 业务：票据/凭证贴现 与 承兑/凭证销售）
  ├→ 合作伙伴 1（C 业务：冲存款）
  ├→ 合作伙伴 2（D 业务：贸易套利指导）
  ├→ 合作伙伴 3（E 业务：债券投资相关服务）
  ├→ 合作伙伴 4（F 业务：摆账/亮资）
  ├→ 合作伙伴 5（G 业务：专利实缴）
  └→ 合作伙伴 6（H 业务：贸易带量）
```

**关键特征：**

* 常松阳部是**唯一的前端入口**：

  * 流量集中在兼职业务员网络
  * 所有 8 个业务的需求都从这里被"捞出来"

* 后端是**专业分工的多节点**：

  * 冷部专注 A/B（票据与凭证主业）
  * 其他业务交由专业合作方处理，我们收获居间/分成

* 对同一个企业客户：

  * 可以同时提供多个业务 → 一客多吃
  * 我们站在"财务解决方案中台"的位置，而不是单一业务供应商。

## 二、8 个业务在整体里各自扮演什么角色？

> 详细字段请看《00_核心文档/8个业务清单更新版.md》，
> 这里只讲「在整体棋盘上，各业务的定位」。

### 2.1 A/B：票据与凭证主战场（现金引擎）

* **A 业务：票据/凭证贴现**

  * 场景：企业手上有远期票据/凭证（银票、商票、电子债权凭证等），需要快速变现。
  * 作用：带来**即时现金流与利润**，也是我们对接银行、票据通道、资金方的主入口。

* **B 业务：承兑/凭证销售（企业付款成本优化）**

  * 场景：企业要付款，但不想全用现金；希望"既能结账，又能省钱"。
  * 作用：

    * 对应 A 业务的逆向操作：「收票 + 卖票」形成闭环；
    * 帮客户优化付款结构（现金+票据），我们赚差价 + 服务费。

> 可以粗暴理解为：
> **A = 收票端赚钱，B = 出票端赚钱**，
> 两端打通之后，一部分票可以在内部完成「买入→卖出」闭环。

### 2.2 C/D/F/G/H：围绕企业资金与规模问题的"周边业务"

这些业务不一定天天发生，但**一旦需求出现，客单价很大**，同时强化我们在企业心中的"财顾+中台"位置。

* **C 冲存款**：

  * 帮银行网点完成存款任务 → 撮合短期资金方
  * 我们站在居间位置，赚撮合服务费
  * 与 A/B 有天然协同：贴现出来的资金也可以成为 C 业务的"资金方"。

* **D 贸易套利指导**：

  * 帮企业设计真实贸易+票据/凭证组合，做结构化套利
  * 对标的是"高阶财务/投行思维"，属于**智力密集型服务**。

* **E 债券投资服务（债券配置顾问服务）**：

  * 帮有闲置资金的企业老板，在自己的账户里做以债券为主的稳健资金配置
  * 由债券配置顾问团队（陈部：国债/利率债；姜部：企业债/城投债）提供策略建议
  * 我们负责需求诊断与对接，不代持资金、不代客理财
  * 更偏"理财+机构资金配置"的角色，解决企业"3-12个月闲置资金"的配置需求

* **F 摆账（亮资）**：

  * 企业在招投标、授信、评级等关键节点，需要账户上真实显示一笔资金
  * 通过与外部资金方签订短期借款/资金拆借协议，短期将资金借入对公账户实现显账
  * 到期按约定归还并支付资金成本与服务费，通过合规方式在账户上"展示余额"

* **G 专利实缴**：

  * 用知识产权作为无形资产完成注册资本实缴
  * 针对的是"注册资本写得很大，但没实缴"的企业老板。

* **H 贸易带量**：

  * 帮企业通过真实贸易做大账面规模（销售额、采购额）
  * 反向支撑 A/B/F 等业务（票据体量、亮资、银行综合授信）。

> 简单一句话：
>
> * A/B = 现金引擎
> * C/D/F/G/H = 「规模 + 资质 + 投资」的周边业务
>
> 我们的优势不是每个都自己干，而是通过合作伙伴，把它们纳入一个「统一入口」。

## 三、组织结构：前端 / 兼职网络 / 后端多节点

### 3.1 总体结构图（文字版）

```text
企业客户（制造 / 贸易 / 建筑 / 科技…）
            │
            │ 需求挖掘 & 咨询
            ▼
【前端：常松阳部】
  ├ 流量入口（兼职业务员网络、内容曝光）
  ├ 统一接单（8 个业务）
  ├ 需求识别（一次性看全企业财务诉求）
  └ 订单分发（路由到对应后端）

            │
            │ 订单 & 资料
            ▼
【后端：专业处理】
  ├ 冷部（票据/凭证专家，负责 A/B）
  ├ 存款合作方（C）
  ├ 套利顾问（D）
  ├ 债券/资金合作方（E）
  ├ 资金方 & 合规团队（F）
  ├ 知识产权机构（G）
  └ 贸易公司/产业链企业（H）
```

### 3.2 兼职业务员网络的位置

```text
【兼职业务员】
  ├ 每天发圈 / 短视频 / 社群，投放 8 个业务的素材
  ├ 识别企业客户的多重需求（贴现 / 付款 / 实缴 / 亮资 / 带量…）
  ├ 把意向客户统一移交给常松阳部
  └ 不直接操作业务，不解释复杂结构
```

核心设计：

* 前端只负责**发现机会 + 建立信任 + 把单子丢给总部**；
* 后端负责**专业判断 + 合同+风控+操作**；
* 兼职业务员不背业务细节，只背"问什么问题 + 把资料收好"。

## 四、三大盈利模式

### 4.1 模式一：A/B 票据差价（高频小单）

**逻辑：**

```text
A 业务：以 X 价格收票（贴现）
B 业务：以 Y 价格出票（卖给需要付款/理财的客户）
差价：Y - X = 我们的毛利
```

特点：

* 单笔利润不一定非常大，但可以高频
* 冷部专业能力越强，定价与匹配效率越高
* 和"远期支票"库存管理、通道谈判、风控直接相关

### 4.2 模式二：合作伙伴分成（中低频中客单）

**公式：**

```text
常松阳部获客 + 合作伙伴交付 = 服务费 / 利润分成
```

* 我们不搭重资产团队，而是输出：

  * 客户
  * 需求定义
  * 协调与监督
* 合作方负责执行与大部分操作成本
* 我们拿：20%–50% 不等的分成（具体按业务谈）

适用业务：C/D/E/F/G/H。

### 4.3 模式三：同一客户多重变现（LTV 放大器）

这是整个设计里最关键的杠杆。

**制造企业示例：**

```text
- 收到下游票据/凭证 → A 业务（贴现变现）
- 要付上游货款 → B 业务（承兑/凭证付款省钱）
- 注册资本没实缴 → G 业务（专利实缴）
- 想做大规模 → H 业务（贸易带量）
- 招投标要证明有钱 → F 业务（摆账）
```

**贸易公司示例：**

```text
- 大量银承/凭证 → A 业务（贴现）
- 采购货物付钱 → B 业务
- 想通过结构化贸易套利 → D 业务
- 要和银行谈授信 → H + F 业务配合
```

**一句话：**

> 获客成本只付一次，
> 但一个客户可以在 2–5 个业务上产生收入，
> 客户越"复杂"，我们越有价值。

## 五、客户全生命周期：从"一个需求"变成"全局财务顾问"

### 5.1 六个阶段的客户旅程

```text
阶段 1：进入视野
  - 通过朋友圈、短视频、转介绍等被触达
  - 对"远期支票变现 / 省钱付款 / 实缴 / 亮资"产生兴趣

阶段 2：单点切入
  - 通常从 A 贴现 或 B 承兑付款 其中一个切入
  - 做一次小单试水，建立基本信任

阶段 3：需求盘点
  - 由常松阳部/核心团队进行系统提问：
    - 收票情况？
    - 付款方式？
    - 注册资本与实缴？
    - 银行授信与招投标？
    - 是否有长期资金/理财需求？
  - 识别出 C–H 的潜在需求

阶段 4：多业务组合服务
  - 为客户设计「业务套餐」：
    - 当期：A/B + 某一项 C–H 业务
    - 中期：配合银行授信、亮资、带量
  - 形成"财务顾问 + 中介平台"角色

阶段 5：长期合作与复购
  - 每次有新的票据/付款/实缴/招投标需求，优先想到我们
  - 客户可被纳入"重点客户池"，由专人跟进

阶段 6：转介绍与生态效应
  - 老客户介绍同行/供应商/客户
  - 在一个产业链里做到"节点型服务商"
```

## 六、对业务员培训与工具包的启示

这部分是本篇对运营层面的直接指导。

### 6.1 培训重点：深度 vs 广度

* A/B 业务（主战场）：

  * 要求**深入掌握**：流程、话术、风险点、合规要点
* C/D/E/F/G/H 业务：

  * 要求**会识别 + 会提问**：

    * 能听出"啊，这个是摆账需求""这个是实缴需求"
    * 会用标准话术把需求和资料收回来
  * 业务细节交给总部与合作方

### 6.2 工具包"四件套"需要覆盖 8 个业务

1. **业务知识手册**

   * A/B：详版
   * C–H：简版（场景+识别问题+移交标准）

2. **展业话术大全**

   * 每个业务至少有：

     * 开场白
     * 需求挖掘问题
     * 异议处理（安全/收益/合规）

3. **朋友圈与短视频素材包**

   * 8 个业务都有对应素材
   * 同一客户可以通过不同入口被种草

4. **操作与移交手册**

   * 统一说明：

     * 客户要给哪些资料？
     * 在系统里怎么录？
     * 哪些情况直接拒绝或转给总部判断？

## 七、小结：一句话商业模式

可以用来写在 README / 招募页 / 对内说明里：

> **三湘票据 = 以票据/凭证为起点的企业资金解决方案中台。**
>
> * 前端用兼职业务员网络统一获客
> * 后端用自营 + 合作伙伴完成 8 个业务专业交付
> * 通过 A/B 业务提供现金解决方案，通过 C–H 业务解决规模、资质、投资与合规问题
> * 对同一个企业客户，多次、多维度赚钱，但始终站在"帮他设计资金路径"的位置。

## 📌 核心定位

**B业务是三湘票据的护城河业务。**

- A业务（贴现）：红海竞争，客户可以找银行、金融机构、任何中介
- B业务（卖票）：**供给端被中介控制**，企业想买票/凭证，必须找中介

**战略方向**：
1. 强化供应端 → 建立票据/凭证库存数据库
2. 主动服务 → 不等客户问，主动设计省钱方案
3. 工具赋能 → 开发计算器/设计器，让客户自己算、自己选

## 一、B业务供应端建设

### 1.1 当前状态

- 有几个熟悉的持票/持凭证资方
- 但没有系统化管理
- 客户来了才去问"有没有货"

### 1.2 目标状态

```
【供应端数据库】
┌─────────────────────────────────────────┐
│  资方管理                                │
│  - 资方名称、联系方式、合作历史          │
│  - 擅长票种/凭证类型                     │
│  - 价格区间、响应速度                    │
│  - 库存更新频率                          │
└─────────────────────────────────────────┘
          ↓
┌─────────────────────────────────────────┐
│  库存管理                                │
│  - 当前有什么票/凭证                     │
│  - 金额区间、期限、价格                  │
│  - 实时/每日更新                         │
└─────────────────────────────────────────┘
          ↓
┌─────────────────────────────────────────┐
│  主动推荐                                │
│  - 客户来了，直接摆出库存推荐            │
│  - 甚至主动给老客户推方案                │
│  - "X总，这批银承价格很好，您要不要？"   │
└─────────────────────────────────────────┘
```

### 1.3 待建设内容

- [ ] **资方通讯录**：整理所有持票/持凭证的合作方
- [ ] **库存表模板**：飞书多维表/Excel，记录实时库存
- [ ] **价格监控**：每日/每周更新各票种价格
- [ ] **主动推送机制**：老客户微信群/私聊推送优质库存

## 二、19种凭证分析（待深度研究）

### 2.1 研究目标

从19种电子凭证中，找出**最适合推广给企业付货款**的凭证类型。

### 2.2 评估维度

| 维度 | 说明 |
|------|------|
| **省钱幅度** | 相比现金付款能省多少？（0.4%-8%区间内具体多少） |
| **开通难度** | 企业开通账户的门槛高不高？ |
| **供应商接受度** | 供应商愿不愿意收这种凭证？ |
| **我方供给能力** | 我们能不能稳定拿到这种凭证？ |
| **操作复杂度** | 流程是否简单？ |
| **适用企业类型** | 什么行业/规模的企业最适合？ |

### 2.3 初步假设（待验证）

| 凭证类型 | 推广优先级 | 理由 |
|---------|-----------|------|
| **银行承兑汇票** | ⭐⭐⭐⭐⭐ | 最通用，供应商接受度最高 |
| **云信** | ⭐⭐⭐⭐ | 央企供应链常见，省钱幅度大 |
| **建信融通** | ⭐⭐⭐⭐ | 建筑行业适用 |
| **中企云链** | ⭐⭐⭐⭐ | 多行业适用 |
| **商业承兑汇票** | ⭐⭐⭐ | 风险稍高，但省钱更多 |
| 其他凭证 | 待研究 | 需逐个分析 |

### 2.4 深度研究问题清单

- [ ] 19种凭证的省钱幅度对比？

## 三、省钱计算器（主推工具）

### 3.1 产品定位

**让企业主3分钟算清楚：用票/凭证付货款能省多少钱。**

### 3.2 用户场景

```
场景1：企业主自己用
"我要付100万货款，用什么方式最省钱？"
→ 输入金额、要求
→ 工具推荐3个方案
→ 企业主自己选

场景2：合伙人给客户演示
"X总，我帮您算一下，您这100万货款..."
→ 当场演示计算过程
→ 客户直观看到省钱效果
→ 促成成交
```

### 3.3 功能设计

**输入项**：
- 付款金额（如：100万）
- 付款时间要求（如：30天内、60天、90天）
- 供应商类型（如：是否接受票据、是否已开通凭证账户）
- 特殊要求（如：要开发票、要公对公）

**输出项**：
```
【推荐方案1】银行承兑汇票
- 省钱金额：约4,000-6,000元（示例值）
- 操作难度：⭐（简单）
- 供应商接受度：高
- 我方报价：99.4万（示例值）
- 适合理由：最通用，供应商容易接受

【推荐方案2】云信/中企云链凭证
- 省钱金额：约6,000-8,000元（示例值）
- 操作难度：⭐⭐（需开通账户）
- 供应商接受度：中（需供应商也开通）
- 我方报价：99.2万（示例值）
- 适合理由：省钱更多，但需要双方都开通

【推荐方案3】商业承兑汇票
- 省钱金额：约8,000-15,000元（示例值）
- 操作难度：⭐⭐⭐（风险稍高）
- 供应商接受度：中低（需信任基础）
- 我方报价：98.5万（示例值）
- 适合理由：省钱最多，但需评估风险

⚠️ 以上数据为示例值，实际价格以成交时为准
```

### 3.4 实现方式（待定）

| 方式 | 优点 | 缺点 | 开发成本 |
|------|------|------|---------|
| **Excel/飞书表格** | 快速上线 | 不够智能 | 低 |
| **微信小程序** | 用户体验好 | 开发成本高 | 高 |
| **H5网页** | 易分享 | 需要开发 | 中 |
| **Claude AI对话** | 智能推荐 | 需要训练 | 中 |

**建议**：先用Excel/飞书表格做MVP，验证需求后再开发小程序

### 3.5 待解决问题

- [ ] 各凭证类型的实时价格如何获取？
- [ ] 推荐逻辑如何设计？（基于什么规则推荐）

## 四、贷款设计器（增值工具）

### 4.1 产品定位

**帮企业主找到最适合的贷款产品，找不到就给适配建议。**

### 4.2 核心逻辑

```
【输入】企业当前条件
- 成立时间
- 年营业额/流水
- 有无抵押物
- 有无发票
- 信用状况
- 贷款金额需求
- 贷款期限需求

【输出1】符合条件的贷款产品
- 产品A：XX银行发票贷，额度XX万，利率XX%
- 产品B：XX银行流水贷，额度XX万，利率XX%
- ...

【输出2】不符合条件时的适配建议
"您当前不符合XX贷款条件，但可以通过以下方式适配："

建议1：贸易带量（H业务）
- 操作：通过我们做大贸易流水
- 周期：4-6个月
- 效果：可获得银行无抵押贷款300-500万
- 如果不计较利息，甚至可达千万级

建议2：专利实缴（G业务）
- 操作：用专利完成注册资本实缴
- 效果：提升企业资质，增加贷款额度

建议3：票据质押
- 操作：用持有的票据做质押
- 效果：快速获得短期资金
```

### 4.3 贷款产品库（待建设）

需要整理市场上常见的贷款产品：

| 贷款类型 | 典型产品 | 基本条件 | 额度范围 | 利率范围 |
|---------|---------|---------|---------|---------|
| 发票贷 | 各银行 | 有真实发票 | 年开票5%-30% | 待研究 |
| 流水贷 | 各银行 | 有稳定流水 | 待研究 | 待研究 |
| 抵押贷 | 各银行 | 有房产/设备 | 抵押物价值70% | 待研究 |
| 信用贷 | 各银行 | 信用良好 | 待研究 | 待研究 |
| 供应链贷 | 核心企业 | 有订单/应收 | 待研究 | 待研究 |

### 4.4 H业务联动（重点）

**贸易带量→银行贷款 路径**：

```
【客户现状】
- 成立时间短，或流水不够
- 银行不给贷款

【我们的方案】
通过H业务（贸易带量）做大流水
    ↓ 4-6个月
银行认可的贸易流水记录
    ↓
申请无抵押贷款
    ↓
获得300-500万（正常）
甚至1000万+（不计较利息）

【关键卖点】
"凭空给企业创造贷款资格"
```

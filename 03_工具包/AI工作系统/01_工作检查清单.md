## 📋 通用工作流程检查清单

### 任务开始前

- [ ] **理解任务本质**
  - [ ] 明确任务目标是什么？
  - [ ] 理解业务逻辑和背景
  - [ ] 识别影响范围（哪些文档会受影响？）

- [ ] **搜索先行**
  - [ ] 遇到不确定信息，先搜索文档
  - [ ] 查找已有相关信息
  - [ ] 建立信息地图（相关文档位置）

- [ ] **影响分析**
  - [ ] 列出所有可能受影响的文档
  - [ ] 识别文档间的依赖关系
  - [ ] 建立修改优先级

---

### 任务执行中

- [ ] **系统性执行**
  - [ ] 按优先级逐个修改
  - [ ] 确保修改的一致性
  - [ ] 记录修改内容

- [ ] **实时验证**
  - [ ] 每修改一个文档，验证是否正确
  - [ ] 检查是否有语法错误
  - [ ] 检查格式是否统一

---

### 任务完成后（强制执行）

- [ ] **完整性验证**
  - [ ] 所有相关文档都已修改？
  - [ ] 所有提到该信息的地方都已更新？
  - [ ] 没有遗漏的文档？

- [ ] **一致性检查**
  - [ ] 所有文档中的信息是否一致？
  - [ ] 是否有矛盾的地方？
  - [ ] 优先级、费用、定位是否统一？

- [ ] **反思与改进**
  - [ ] 这次犯了什么错误？
  - [ ] 为什么会犯这个错误？
  - [ ] 下次如何避免？
  - [ ] 更新错误清单和最佳实践

## 🚨 常见错误清单（持续更新）

### 错误1：留空让用户填写
- **错误表现**：遇到不确定信息，留空或写"[待填写]"
- **正确做法**：先搜索文档，查找已有信息
- **检查方法**：遇到不确定信息时，先grep或codebase_search

### 错误2：只改明确指出的文件
- **错误表现**：用户说改3个文档，就只改这3个
- **正确做法**：系统性检查所有相关文档
- **检查方法**：使用检查清单，列出所有可能受影响的文档

### 错误3：不理解业务逻辑就改
- **错误表现**：机械执行，不理解为什么这样改
- **正确做法**：先理解业务逻辑，再执行修改
- **检查方法**：修改前先问"为什么"，理解后再改

### 错误4：没有验证完整性
- **错误表现**：修改后没有检查是否遗漏
- **正确做法**：建立检查清单，逐个验证
- **检查方法**：使用grep搜索所有提到该信息的地方

### 错误5：没有同步更新相关文档
- **错误表现**：修改了A文档，但B文档也提到同样信息，没改
- **正确做法**：修改前先搜索，找出所有相关文档
- **检查方法**：使用grep或codebase_search全局搜索

### 错误6：没有先理解设计意图就动手操作（目录结构错误）
- **错误表现**：看到文件系统中的问题（如两个04目录），就立即尝试解决，没有先理解正确的设计意图
- **错误案例**：看到`04_工具包`和`04_SOP标准流程`两个04目录，就假设需要解决序号冲突，想把`04_工具包`改成`05_工具包`
- **正确做法**：
  1. 先阅读README.md，理解正确的目录结构设计
  2. 以README为准，而不是以当前文件系统为准
  3. 分析问题的本质（是设计问题还是执行问题）
  4. 再提出解决方案
- **检查方法**：
  - 遇到目录结构问题时，先读README.md的"目录结构"部分
  - 确认正确的设计意图
  - 检查Git历史，了解目录来源
  - 再决定是合并、移动还是删除
- **根本原因**：犯了"看到症状就开药"的错误，而不是"先诊断再治疗"

## ✅ 最佳实践清单（持续积累）

### 实践1：修改业务优先级时
1. 先搜索所有提到"优先级"、"P0"、"P1"的文档
2. 建立修改清单
3. 按优先级逐个修改
4. 最后全局搜索验证

### 实践2：修改费用数据时
1. 先搜索所有提到该费用的文档（如"3-5%"）
2. 检查是否有其他表述方式（如"3%-5%"）
3. 统一修改
4. 验证是否还有遗漏

### 实践3：修改业务定位时
1. 先搜索所有提到该定位的文档（如"杀手锏"）
2. 检查业务详解、话术、培训文档
3. 统一修改
4. 更新记忆口诀

### 实践4：修改JD时
1. 检查JD库、面试评估表、面试提纲
2. 检查BOSS直聘JD
3. 检查进度追踪器中的任务状态
4. 确保所有信息一致

### 实践5：遇到不确定信息时
1. 先搜索文档（grep或codebase_search）
2. 如果找不到，再问用户
3. 记录到文档中，避免下次再问
